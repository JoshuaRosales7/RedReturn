# Architecture

```
Browser (Next.js static export, React 19, Zustand, Recharts, R3F)          FastAPI service (Python 3.12, NumPy, rasterio)
 ├─ AppShell + 8 tabs (components/tabs)                                      ├─ routers/   system · terrain · routes · mission · ares
 ├─ lib/store.ts   single state + live-API / snapshot fallback               ├─ services/  planning (orchestration) · ares (tool layer)
 ├─ lib/mars.ts    closed-form mirror of the mission model (golden-tested)   ├─ scientific/ geodesy · dem · routing · mission · risk · emergency
 ├─ lib/api.ts     timeout + cancellation, typed errors                      ├─ datasets/  provenance registry + checksum status
 └─ public/data/demo-snapshot.json   precomputed demo (labelled, offline)    ├─ data/dem/  cached NASA MOLA windows (+ provenance JSON)
                                                                              └─ errors.py · limits.py (typed errors, rate/body limits)
NASA Mars Trek WMTS  ← tiles fetched directly by the browser (display only)
USGS/NASA MOLA GeoTIFF ← read once by scripts/build_mola_windows.py (HTTP range requests)
```

## Single calculation path
`scientific/mission.py::project_mission` is used by the point estimate, the Monte Carlo (vectorised), the emergency engine (from a mid-mission state) and ARES. The browser never recomputes terrain, routes, risk or incidents; it only mirrors the closed-form point estimate in `lib/mars.ts`, and `tests/golden/mission_vectors.json` (generated by Python) is asserted by both test suites. If the API is unreachable, the demo scenario is served from `demo-snapshot.json`, generated by the same engine and labelled "Precomputed snapshot"; other inputs show an explicit "API offline" error rather than invented numbers.

## Data flow
origin/target/config/stops → `/api/routes/alternatives` (DEM tile lookup → four routes → per-route mission evaluation → recommendation + reasons) → Terrain/Planner/Overview. Risk, Emergency and ARES re-plan the recommended route server-side (cached by `lru_cache`) and return results with hashes/metadata.

## Quality states
`terrain_status`: `insufficient-data` (flat legacy routes) or `dem-evaluated-coarse`. `certification` is always `NOT_CERTIFIABLE`. Samples are `cell_value | interpolated | nodata | outside_coverage`.

## Security / reliability
Typed error envelope; Pydantic bounds; list caps; grid cap; body cap; per-IP token bucket (600/min, 180/min heavy; env-tunable); CORS allow-list from env, GET/POST only, no credentials; no secrets in the client; optional LLM key server-side only; non-root container with healthcheck. WebGL context-loss recovery on the globe; error boundaries per tab; request cancellation on every store action.
